# 06 · 多游戏架构与新增游戏指南

本文说明「大厅 + 游戏模块」的分层方式、`game/engine.js` 提供的通用能力，以及新增一款游戏时必须同步修改的文件。新增或调整游戏模块前先读本文，再读 [01](01-游戏设计与关卡.md)、[02](02-架构与渲染管线.md)、[04](04-资源与音频清单.md) 中对应的部分。

## 1. 游戏清单

| id | 游戏 | 受众 | 关卡 | 章节 | 页面 | 引擎 | 存档键 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `orchard` | 小兔子的彩虹果园 | 4–7 岁 | 20 | 5 章 × 4 关 | `pages/game/game` | `game/orchard.js` | `bunny-native-progress-v1` |
| `bubble` | 泡泡海洋 | 4–9 岁 | 16 | 4 章 × 4 关 | `pages/bubble/bubble` | `game/bubble.js` | `kids-bubble-progress-v1` |
| `memory` | 动物翻翻乐 | 4–9 岁 | 16 | 4 章 × 4 关 | `pages/memory/memory` | `game/memory.js` | `kids-memory-progress-v1` |
| `band` | 小小乐队 | 4–9 岁 | 16 | 4 章 × 4 关 | `pages/band/band` | `game/band.js` | `kids-band-progress-v1` |

| `tank` | 坦克打气球 | 4–9 岁 | 16 | 4 章 × 4 关 | `pages/tank/tank` | `game/tank.js` | `kids-tank-progress-v1` |
| `lines` | 连线小方块 | 4–9 岁 | 16 | 4 章 × 4 关 | `pages/lines/lines` | `game/lines.js` | `kids-lines-progress-v1` |

- 果园是首款游戏，保留独立的 `OrchardGame` 实现，不复用 `BaseGame`；它的玩法细节见 [01](01-游戏设计与关卡.md) 第 2–9 节。
- 其余六款游戏共用 `game/engine.js` 的 `BaseGame`，只实现各自的玩法、场景与 HUD 扩展。
- 七款游戏的静音状态共用 `bunny-native-muted-v1`，切换游戏后保持一致。

## 2. 分层

```
pages/index/index.uvue            游戏大厅（UVue 原生组件）
   └─ games[] → uni.navigateTo(route)
        ├─ pages/game/game.uvue       → OrchardGame（独立实现）
        ├─ pages/bubble/bubble.uvue   → BubbleGame  ┐
        ├─ pages/memory/memory.uvue   → MemoryGame  │
        ├─ pages/band/band.uvue       → BandGame    │
        ├─ pages/blocks/blocks.uvue   → BlocksGame  ├ extends BaseGame
        ├─ pages/tank/tank.uvue       → TankGame    │
        └─ pages/lines/lines.uvue     → LinesGame   ┘
                    ↓
game/engine.js                    通用外壳
   ├─ 工具：clamp、rand、lerp、fillRound、strokeRound、drawLabel、wrapLines、drawSparkle、mulberry32
   ├─ 色板：RAINBOW、CHAPTER_COLORS
   ├─ NativeAudio：BGM / 音效 / 语音（每款游戏各持一份上下文）
   └─ BaseGame：状态机、帧循环、布局、HUD、开始页、关卡地图、暂停、庆祝、存档、调试
```

页面层仍然是纯胶水：创建自己的 Canvas（`game-bubble` / `game-memory` / `game-band` / `game-blocks` / `game-tank` / `game-lines`，不能重名）、计算 DPR 与安全区、转发触摸与 `onReady` / `onHide` / `onBackPress` / `onUnload`。玩法、绘制、音频与存档都在引擎层。

## 3. BaseGame 提供的能力

子类通过 `super(options, CONFIG)` 传入 `options`（`canvasContext`、`ctx`、`width`、`height`、`dpr`、`safeTop`、`safeBottom`）与配置表 `CONFIG`。

| 配置字段 | 作用 |
| --- | --- |
| `id` / `name` / `title` / `titleColors` | 路由标识、标题、开始页彩色逐字标题 |
| `kicker` / `tagline` / `startLabel` / `loadingText` | 开始页文案与加载文案 |
| `ageText` / `footer` / `hostName` | 年龄标签、页脚、庆祝卡片上的伙伴名 |
| `iconText` / `meterIcon` | 章节芯片与进度条上的小图标字符 |
| `levels` / `levelsPerChapter` / `chapters` | 关卡表、地图列数、章节短名 |
| `storageKey` / `audioPath` / `bgm` / `sfx` | 存档键、音频目录、BGM 与音效文件名映射 |
| `assets` | key → 图片路径，`loadImages()` 自动全部加载 |

基类处理：

- **生命周期**：`startNewGame()`、`beginLevel()`、`pause()`、`resume()`、`handleHide()`、`handleBack()`、`goHome()`、`nextLevel()`、`replayGame()`、`requestExit()`、`cancelExit()`、`exitToLobby()`、`destroy()`。
- **状态机**：`state`（`loading | start | levelselect | playing | paused | celebrating`）与 `gameMode`（`idle | ready | roundclear | celebrated`），与果园一致。
- **绘制框架**：`draw()` 按 `drawWorld()` → 状态分支 → `drawActors()` → `drawEffects()` → HUD/弹层的顺序执行。
- **通用界面**：开始页、关卡地图、暂停卡片、庆祝卡片、退出确认弹窗、主/次按钮、圆形图标按钮、横幅、首次提示气泡、Toast。
- **反馈系统**：粒子、飘字、彩带、HUD 抖动、连击提示所需的基础设施。
- **音频与存档**：`NativeAudio`、`readProgress()`、`saveProgress()`、共享静音。
- **调试**：`typeof window !== 'undefined'` 时挂载 `window.__kidsGame` 与 `window.__kidsGameType`。

### 3.1 子类可覆盖的钩子

| 钩子 | 用途 | 是否必须 |
| --- | --- | --- |
| `setupLevel(cfg, level)` | 按关卡配置初始化本关数据 | 必须 |
| `resetLevelData()` | 清空本关数组与计时 | 必须 |
| `updatePlay(dt)` | 每帧玩法推进 | 必须 |
| `updateClear(dt)` | 过关动画期间的收尾 | 建议 |
| `drawWorld()` | 场景背景 | 必须 |
| `drawActors()` | 玩法主体（泡泡、卡片、乐器） | 必须 |
| `getObjectiveText()` | 进度条下的目标文案 | 建议 |
| `getStartHint()` | 开始页与首次提示气泡文案 | 建议 |
| `getResultLines()` | 庆祝卡片的标题、正文、统计 | 建议 |
| `drawObjectiveIcon(cx, cy)` | 目标条左侧小图标 | 可选 |
| `drawHostBackdrop(center, bottom, size)` | 开始页伙伴背后的装饰 | 可选 |
| `drawExtraHud(y)` | 额外 HUD（如泡泡的伙伴标记） | 可选 |
| `drawExtraOverlays()` | 额外浮层（如泡泡的连击胶囊、积木的魔法闪光） | 可选 |
| `onTapInPlay(x, y)` | 游戏中点击（非按钮） | 视玩法 |
| `onDragStart/Move/End(x, y)` | 拖拽类玩法（连线）；不覆盖 `touchXxx` | 可选 |
| `activateExtra(id)` | 玩法内的圆钮（坦克的 `tank-fire`） | 可选 |
| `debugState()` 及 `debugXxx()` | 调试快照与推进方法 | 建议 |

不要在子类里重写 `update()`、`draw()`、`touchStart/touchEnd` 或存档函数；需要改变流程时先确认基类钩子是否够用。

## 4. 新增一款游戏的步骤

1. **设计关卡**：16 关 = 4 章 × 4 关，每关只调 1–3 个数值维度；前 4 关不引入失败反馈，第 16 关是终章。数值表与机制写进 [01](01-游戏设计与关卡.md)。
2. **写引擎**：新建 `game/<id>.js`，顶部写 `LEVELS`、`CONFIG`，类继承 `BaseGame`，实现 `setupLevel` / `resetLevelData` / `updatePlay` / `drawWorld` / `drawActors` 与需要的 HUD 扩展。按章变色的游戏要在 `beginLevel()` 里把缓存的 `skyGradient` 置空。
3. **准备资源**：图片放 `static/img/` 对应子目录，动画帧同尺寸；音频放 `static/audio/<id>/`，语音放 `static/audio/<id>/voice/`。全部登记到 [04](04-资源与音频清单.md)。
4. **建页面**：复制任一现有游戏页为 `pages/<id>/<id>.uvue`，改三处：Canvas id（`game-<id>`）、引擎 import、类名；页面背景色与 `pages.json` 的 `backgroundColor` 保持一致。
5. **注册路由**：在 `pages.json` 追加页面，`navigationStyle: custom`、`pageOrientation: portrait`、`app-plus.bounce: none`。
6. **加大厅卡片**：在 `pages/index/index.uvue` 的 `games` 数组追加一项：`id`、`name`、`desc`、`route`、`cover`、`coverBg`、`accent`、`badge`、`chips`。封面图 900×640，卡片高度由脚本按 `coverWidth × 640 / 900` 计算，不要再写死高度。
7. **接调试**：实现 `debugState()` 与至少一个推进方法（如 `debugFinishLevel()`），命名沿用现有约定。
8. **同步文档**：更新 [01](01-游戏设计与关卡.md)、[02](02-架构与渲染管线.md)、[03](03-视觉与交互规范.md)、[04](04-资源与音频清单.md)、本文清单、根 [README](../README.md) 与 [AGENTS](../AGENTS.md)，并在 [docs/README](README.md) 的对照表里确认入口。

### 4.1 命名约定

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 游戏 id | 小写英文，单词间无分隔 | `bubble`、`memory`、`band`、`blocks`、`tank`、`lines` |
| 页面路径 | `pages/<id>/<id>.uvue` | `pages/memory/memory.uvue` |
| Canvas id | `game-<id>` | `game-band` |
| 图片目录 | `static/img/<资源类别>/`，key 即文件名 | `static/img/animals/cat.png` |
| 音频目录 | `static/audio/<id>/`，`bgm.mp3` + 音效 | `static/audio/bubble/pop.mp3` |
| 语音目录 | `static/audio/<id>/voice/`，固定五个文件 | `start` `clear` `great` `final` `replay` |
| 存档键 | `kids-<id>-progress-v1` | `kids-band-progress-v1` |

语音文件是固定契约：开始 `start`、普通过关 `clear`、每 4 关 `great`、终章 `final`、重玩 `replay`。新增游戏如果缺少其中任何一个，对应场景会静默无声。

### 4.2 存档结构

新游戏统一保存：

```json
{ "unlocked": 1, "completed": [], "best": {} }
```

- `unlocked` 夹在 1–`MAX_LEVEL`；`completed` 去重并过滤越界值；`best` 按关卡保存最高分。
- 读取失败回退初始值，不阻断启动。
- 改结构时递增键名后缀，并同步 [02](02-架构与渲染管线.md) 与本表。

## 5. 设计约束（与果园一致）

- 没有失败态、没有倒计时、没有生命值；失误只给提示、清连击。积木堆到顶用「彩虹魔法」清场、连线无解时自动重排，都属于这条约束的落地方式。
- 单指点击或拖动完成全部操作；点击目标视觉尺寸 ≥ 34px，命中区再外扩 10px 左右。按钮类操作必须在按下当帧就有反应；积木的按住加速在 0.3 秒后才提速，避免短按被误判成加速。
- 每局 40–90 秒；前三关必须能被目标年龄儿童在无人指导下完成。
- 同一关的装饰由 `mulberry32(level × 7919 + 41)` 生成，保持每次进入一致。
- 每帧按钮重新注册，绘制顺序即层级；弹层末尾过滤 `buttons`。玩法内的圆钮也走按钮系统（`activateExtra`），不要另建命中列表。
- 绘制统一使用 `fillRound` / `strokeRound` / `drawLabel`，不重复实现圆角与文字。
- 单帧异常只记录日志，不中断循环。

## 6. 验收

新增游戏至少验证：

- [ ] 冷启动进入大厅，卡片封面完整、比例正确，点击进入对应游戏。
- [ ] 加载页 → 开始页 → 第 1 关，首次提示在首次操作后消失。
- [ ] 每章至少一关可通关，庆祝卡片文案、统计与语音正确。
- [ ] 第 16 关显示终章文案并播放 `final` 语音。
- [ ] 暂停、Android 物理返回、切后台恢复后音频不重叠。
- [ ] 静音与果园状态一致，重启后保持。
- [ ] 杀掉进程重进，关卡地图解锁状态正确。
- [ ] 至少一台刘海屏与一台 16:9 屏上 HUD、按钮、庆祝卡片不重叠。
