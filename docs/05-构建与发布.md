# 05 · 构建与发布

本文说明如何运行、打包与发版，以及版本号、ABI、签名、产物与提交纪律。日常开发用 HBuilderX 运行；本地 Android 打包用 [`scripts/build-android.sh`](../scripts/build-android.sh) 一键完成。

## 1. 环境

| 项目 | 要求 | 当前验证环境 |
| --- | --- | --- |
| 系统 | macOS（Apple Silicon） | macOS 27 / arm64 |
| HBuilderX | 5.26 及以上 | `5.26.2026091802` |
| uni-app x 离线 SDK | 官方 Vapor SDK 5.26 | `Android-uni-app-x-vapor-SDK@101163-5.26` |
| JDK | **21 及以上**（推荐 25） | Temurin 25.0.3 |
| Android SDK | Platform 36、Build-Tools 36 | `~/Library/Android/sdk` |
| Gradle | 9.2.1，由宿主 wrapper 提供 | 9.2.1 |
| 其他命令 | `rsync`、`unzip`、`plutil`、`perl` | macOS 自带 |
| 项目依赖 | 无 npm、无 lockfile、无 `node_modules` | — |

> **JDK 必须是 21+。** UTS 自动注册插件 `UTSAutoRegisterPlugin` 的 class 文件版本是 65（Java 21），用 JDK 17 执行 Gradle 会报
> `UnsupportedClassVersionError ... class file version 65.0`。
> HBuilderX 自带 Corretto 17，只够启动 Gradle；宿主 `gradle/gradle-daemon-jvm.properties` 指定了 JDK 25，缺失时 Gradle 会自动下载。为了避免首次打包等待，建议直接安装 JDK 21/25，或让脚本找到 `~/.gradle/jdks` 中已有的 JDK。
>
> `scripts/build-android.sh` 会依次寻找 `JAVA_HOME`、`~/.gradle/jdks`、HBuilderX 自带 JDK、系统 `java`，优先选 21+；找不到 21+ 时才回退到 17（由 Gradle daemon 配置补 25）。

本项目**没有 `node_modules`、无 lockfile**，不要执行 `npm install` / `pnpm install`。构建脚本只用 Bash 和 macOS 自带命令，不依赖 Node。

## 2. 日常运行

1. HBuilderX 打开本仓库根目录（包含 `manifest.json` 的目录）。
2. 菜单「运行 → 运行到手机或模拟器 → 运行到 Android App 基座」。
3. `.hbuilderx/launch.json` 已配置标准运行：

```json
{
  "version": "1.0",
  "configurations": [{ "playground": "standard", "type": "uni-app:app-android" }]
}
```

运行产物位于 `unpackage/dist/dev/app-android/`，不提交。

### 2.1 命令行运行（可选）

```bash
# 查看可用设备
/Applications/HBuilderX.app/Contents/MacOS/cli devices list

# 编译并运行到 Android 设备（纯 CLI 模式）
/Applications/HBuilderX.app/Contents/MacOS/cli launch app-android --project "$PWD" --deviceId <serial>

# 仅编译，不启动基座
/Applications/HBuilderX.app/Contents/MacOS/cli launch app-android --project "$PWD" --compile true

# 使用界面模式启动
/Applications/HBuilderX.app/Contents/MacOS/cli launch app-android --project "$PWD" --ui
```

常用参数：`--project`（项目名或绝对路径）、`--deviceId`、`--playground standard|custom`、`--native-log true`、`--pagePath` / `--pageQuery`（直达指定页面）。完整说明见 HBuilderX 官方文档 `hx.dcloud.net.cn/cli/launch-app`。

## 3. 打包原理

本地打包分成四段，任何一段都可以单独重跑：

```text
源码 + static 资源
      │  HBuilderX CLI / 发行
      ▼
unpackage/resources/app-android/<appid>/www/   ← 字节码、app-service.js、静态资源
      │  rsync
      ▼
精简宿主 uniappx/src/main/assets/apps/<appid>/www/
      │  Gradle :app:assembleRelease
      ▼
app/build/outputs/apk/release/app-release-unsigned.apk
      │  apksigner（正式 keystore）
      ▼
build/huanle-games-<versionName>.apk
```

- **HBuilderX 负责“应用资源”**：把 `.uvue`、游戏 JS、图片、音频编译成 App 端可执行的 `www/` 目录。CLI 与 HBuilderX 使用同一套编译器。
- **宿主负责“原生壳”**：`xvnativeproject` 提供 Android 启动 Activity、uni-app x 运行时、Canvas/音频/存储等原生 AAR。
- **Gradle 负责合并与打包**：把 `www/` 放进 assets，编译 dex、合并 so，生成未签名 APK。
- **apksigner 负责签名**：v2/v3 签名后才可安装；签名证书必须与历史版本一致，否则无法覆盖安装。

### 3.1 为什么使用精简宿主

官方 SDK 的完整 `xvnativeproject` 包含地图、扫码、人脸、直播、广告、推送等全部示例模块，直接打包约 **166 MB**。本项目只保留：

- Canvas：`uni-canvas-component`、`uni-canvas-dom2`
- 音频：`uni-createInnerAudioContext`、`audio-mp3aac`、`uni-media`、ExoPlayer
- 存储与系统信息：`uni-storage`、`uni-getSystemInfo`、`uni-getAppBaseInfo`、`uni-getDeviceInfo` 等
- 基础能力：`app-runtime`、`uts-runtime`、`ext-component`、Fresco、Skia 等运行时必需库

当前 1.2.0 的 APK 约 **51 MB**，构成大致为：

| 内容 | 大小 | 说明 |
| --- | --- | --- |
| 原生 `.so` | 36.1 MB / 13 个 | `libuniappx.so` 26 MB、Skia、Freetype、UTS 等 |
| `classes*.dex` | 20.8 MB / 3 个 | 运行时、Fresco、ExoPlayer、UTS 注册代码 |
| 游戏资源 | 4.0 MB | 四款游戏的图片、音频、人声 |
| 其他 | 少量 | manifest、资源表、启动图标 |

宿主模板固定在 [`scripts/native-host/`](../scripts/native-host/)，每次打包不会重新从完整示例工程复制依赖。

## 4. 首次准备（每台机器一次）

### 4.1 确认工具链

```bash
# HBuilderX CLI
ls -l /Applications/HBuilderX.app/Contents/MacOS/cli

# JDK（21+；本文验证的是 25）
java -version

# Android SDK
echo "${ANDROID_HOME:-$HOME/Library/Android/sdk}"
ls "${ANDROID_HOME:-$HOME/Library/Android/sdk}/platforms" | tail
ls "${ANDROID_HOME:-$HOME/Library/Android/sdk}/build-tools" | tail
```

如果 JDK 不在 `JAVA_HOME`，可临时指定（也可改用任意已安装的 JDK 21+ 目录）：

```bash
# 使用 Gradle 已下载的 JDK 25；若结果为空，改成实际 JDK 21+ 根目录
export JAVA_HOME="$(find "$HOME/.gradle/jdks" -type f -path '*/bin/java' | sort -r | head -1 | sed 's#/bin/java$##')"
```

也可以安装任意 JDK 21/25，脚本会通过 `JAVA_HOME` 或系统 `java` 找到它。

### 4.2 准备签名证书

发版证书必须长期保存并复用，**不要提交仓库，也不要换证书**。本项目使用：

| 文件 | 用途 |
| --- | --- |
| `build/signing/bunny-orchard-release.jks` | 正式签名证书 |
| `build/signing/keystore.properties` | 别名与证书路径（已忽略提交） |
| `build/signing/storepass.txt` | 单行证书库密码，权限 `600` |

别名固定为 `bunnyorchard`。如果私钥密码与证书库密码不同，额外准备一个单行密码文件，并通过 `KEY_PASSWORD_FILE` 传入。

新机器没有证书时，需要从原发版机器安全拷贝；重新生成会导致已安装用户无法覆盖升级。

### 4.3 初始化宿主缓存

宿主缓存默认放在：

```text
~/Library/Application Support/GameApp/uni-app-x-vapor-5.26/
├── SDK/                 # 官方 AAR（约 226 MB）
├── plugins/             # UTS / auto-register Gradle 插件
└── xvnativeproject/     # 精简宿主（来自 scripts/native-host 模板）
```

从官方 SDK 初始化（在仓库根目录执行）：

```bash
scripts/setup-native-host.sh --sdk ~/Downloads/Android-uni-app-x-vapor-SDK@101163-5.26.zip
```

脚本会：

1. 从 zip 或解压目录中找出 `SDK/libs` 与 `plugins`，复制到缓存；
2. 用 `scripts/native-host/xvnativeproject` 覆盖宿主模板；
3. 根据 `manifest.json` 的 appid 创建 assets 目录；
4. 写入 `local.properties`（Android SDK 路径）并校验宿主依赖的 AAR 是否齐全。

如果不指定 `--sdk`，脚本会自动查找：

- `$UNI_X_SDK`、`$UNI_X_SDK_ZIP`、`$UNI_X_SDK_ROOT`
- `/tmp/uni-x-sdk/vapor-sdk-5.26.zip`
- `/tmp/uni-x-sdk/extracted/Android-uni-app-x-vapor-SDK@*`
- `~/Downloads/Android-uni-app-x-vapor-SDK@*`

常用参数：

```bash
scripts/setup-native-host.sh --force          # 重新复制 SDK 原生库
scripts/setup-native-host.sh --dest <目录>    # 自定义缓存目录
```

> 升级 HBuilderX 或离线 SDK 后，必须使用**同版本**的 SDK 重新初始化；否则运行时可能出现模块缺失或版本不匹配。

## 5. 一键打包

在仓库根目录执行：

```bash
scripts/build-android.sh
```

脚本会读取 `manifest.json` 中的 `appid`、`name`、`versionName`、`versionCode`，依次完成：

1. 调用 HBuilderX CLI 生成发行资源；
2. 用 `rsync --delete` 把资源同步进宿主，清掉旧版本的残留文件；
3. 执行 `./gradlew :app:assembleRelease`，把版本号传给 Gradle；
4. 用 `apksigner` 签名，校验包名、版本号、v2/v3 签名与 4 字节对齐；
5. 输出 APK 并打印大小、SHA-256、证书 SHA-256。

> HBuilderX CLI 需要 HBuilderX 处于打开状态。脚本检测到「未检测到已打开的HBuilderX」时会自动执行
> `cli open --project` 并重试；若自动启动失败，手动打开 HBuilderX 后重跑即可。

成功输出示例：

```text
==> 打包完成
    产物: .../build/huanle-games-1.2.0.apk
    大小: 51M
    SHA-256: ...
    证书 SHA-256: ...
    package: name='com.kidsgame.bunnyorchard' versionCode='103' versionName='1.2.0'
    native-code: 'arm64-v8a'
    日志: .../build/logs/build-YYYYMMDD-HHMMSS.log
```

### 5.1 参数与环境变量

| 参数 | 作用 |
| --- | --- |
| `--skip-compile` | 跳过 HBuilderX 编译，直接用 `unpackage/resources` 中已有资源（仅调试打包流程时用） |
| `--clean` | 打包前执行 Gradle `clean`，排除旧构建缓存影响 |
| `--host <目录>` | 使用指定宿主（默认使用应用支持目录缓存） |
| `--out <文件>` | 指定输出 APK 路径 |
| `--help` | 显示帮助 |

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HBX_CLI` | `/Applications/HBuilderX.app/Contents/MacOS/cli` | HBuilderX CLI |
| `ANDROID_HOME` | `~/Library/Android/sdk` | Android SDK |
| `JAVA_HOME` | 自动查找 | JDK 21+ |
| `NATIVE_HOST` | 缓存宿主 | 覆盖宿主目录 |
| `NATIVE_HOST_CACHE` | `~/Library/Application Support/GameApp/uni-app-x-vapor-5.26` | 宿主缓存根目录 |
| `KEYSTORE_FILE` | `build/signing/bunny-orchard-release.jks` | 证书文件 |
| `KEYSTORE_ALIAS` | `bunnyorchard` | 证书别名 |
| `KEYSTORE_PASSWORD_FILE` | `build/signing/storepass.txt` | 证书库密码文件 |
| `KEY_PASSWORD_FILE` | 与证书库密码相同 | 私钥密码文件（可选） |

示例：

```bash
# 全量重打
scripts/build-android.sh --clean

# 只重跑 Gradle + 签名（已确认资源是最新的）
scripts/build-android.sh --skip-compile

# 输出到自定义路径
scripts/build-android.sh --out /tmp/kids-game-test.apk
```

### 5.2 增量与耗时

| 场景 | 大致耗时 |
| --- | --- |
| HBuilderX 编译资源 | 5–10 秒 |
| Gradle 首次全量构建 | 1.5–2 分钟 |
| 仅改 JS/图片后增量构建 | 20–60 秒 |
| 仅签名 + 校验 | 2–5 秒 |

Gradle 的 daemon 与 configuration cache 会保留在 `~/.gradle` 和宿主 `build/` 中；`--clean` 只清理宿主构建产物，不影响 SDK 缓存。

## 6. 手动打包（排障用）

一键脚本失败时，可以按以下步骤逐段定位。在仓库根目录准备变量：

```bash
export PROJECT_DIR="$PWD"
export APPID=__UNI__B4E2FFE
export HOST="$HOME/Library/Application Support/GameApp/uni-app-x-vapor-5.26/xvnativeproject"
export JAVA_HOME="$(find "$HOME/.gradle/jdks" -type f -path '*/bin/java' | sort -r | head -1 | sed 's#/bin/java$##')"
export PATH="$JAVA_HOME/bin:$PATH"
```

### 6.1 生成发行资源

```bash
# HBuilderX CLI 需要 HBuilderX 已打开；未打开时先执行：
/Applications/HBuilderX.app/Contents/MacOS/cli open --project "$PROJECT_DIR"

/Applications/HBuilderX.app/Contents/MacOS/cli publish app-android \
  --type appResource \
  --project "$PROJECT_DIR"
```

只有输出中包含「编译成功」和「导出 android 成功」才算成功。CLI 在 HBuilderX 未打开时可能返回 0 并只打印提示，不能只看退出码。

产物：

```text
unpackage/resources/app-android/__UNI__B4E2FFE/www/
├── app-service.js
├── app-config.js
├── manifest.json
├── bytes/
└── static/
```

检查 `manifest.json` 的 `version.name/code` 是否与根 `manifest.json` 一致，以及 `app-android.distribute.modules` 是否包含当前用到的原生模块。

### 6.2 同步资源

```bash
rsync -a --delete \
  "unpackage/resources/app-android/$APPID/www/" \
  "$HOST/uniappx/src/main/assets/apps/$APPID/www/"
```

必须使用 `--delete`，否则旧版本的页面、字节码或 `static` 文件会残留，典型症状是启动后报 `GOAL is not defined` 或显示旧关卡。

### 6.3 Gradle 打包

```bash
cd "$HOST"
./gradlew :app:assembleRelease --console=plain \
  -PappVersionCode=103 \
  -PappVersionName=1.2.0
```

未签名产物：

```text
app/build/outputs/apk/release/app-release-unsigned.apk
```

### 6.4 签名与校验

```bash
cd "$PROJECT_DIR"
APKSIGNER="$HOME/Library/Android/sdk/build-tools/36.0.0/apksigner"
$APKSIGNER sign \
  --ks build/signing/bunny-orchard-release.jks \
  --ks-key-alias bunnyorchard \
  --ks-pass file:build/signing/storepass.txt \
  --out build/huanle-games-1.2.0.apk \
  "$HOST/app/build/outputs/apk/release/app-release-unsigned.apk"

$APKSIGNER verify --verbose --print-certs build/huanle-games-1.2.0.apk
```

`apksigner` 默认用证书库密码尝试私钥密码；如果私钥密码不同，追加 `--key-pass file:<私钥密码文件>`。

## 7. 版本管理

版本号只在 [`manifest.json`](../manifest.json) 维护：

| 字段 | 说明 | 当前值 |
| --- | --- | --- |
| `versionName` | 展示版本 | `1.2.0` |
| `versionCode` | 整数，每次发版必须递增 | `103` |
| `appid` | 固定，不修改 | `__UNI__B4E2FFE` |
| `name` | 应用名 | `欢乐游戏` |

打包脚本会把 `versionName/versionCode` 通过 `-PappVersionName` / `-PappVersionCode` 传给 Gradle，并同步宿主的 `strings.xml` 应用名，因此**不再需要手工修改宿主 `build.gradle`**。

发版时同时更新 [`package.json`](../package.json) 的 `version` 与 `displayName`，保持三处一致。包名保持 `com.kidsgame.bunnyorchard`，用于延续已安装用户的本地存档；改品牌名不修改包名与 appid。

## 8. 打包配置

`manifest.json` 中与本项目强相关的字段：

| 字段 | 值 | 含义 |
| --- | --- | --- |
| `uni-app-x.vapor` | `true` | 启用 Vapor 渲染模式 |
| `uni-app-x.vapor-render-target` | `bytecode` | 渲染目标为字节码 |
| `uni-app-x.styleIsolationVersion` | `"2"` | 样式隔离版本，改动需整体回归 |
| `uni-app-x.vapor-default-script-lang` | `ts` | 默认脚本语言 |
| `transformPx` | `false` | 禁用 px 自动转 rpx，Canvas 使用 CSS 像素 |
| `app-android.distribute.abiFilters` | `arm64-v8a`, `x86_64` | 声明支持的 ABI |
| `uniStatistics.enable` | `false` | 关闭 uni 统计，保持零网络请求 |

> 本地精简宿主目前只打入 **arm64-v8a**（`app/build.gradle` 的 `abiFilters`），面向真机。`manifest.json` 同时声明 `x86_64` 是为云打包保留；本机模拟器若为 arm64 可直接安装。需要 x86_64 真机/模拟器包时，应在宿主中加入对应 ABI 的原生库并调整 `abiFilters`，不要只改 manifest。

`pages.json`：大厅 `pages/index/index` 为首页，四个游戏页 `pages/game/game`、`pages/bubble/bubble`、`pages/memory/memory`、`pages/band/band` 为二级页；五页均 `navigationStyle: custom`、`pageOrientation: portrait`、`app-plus.bounce: none`。

## 9. 产物、签名与忽略规则

| 路径 | 内容 | 是否提交 |
| --- | --- | --- |
| `build/*.apk` | 打包产物 | 否（仓库根 `.gitignore` 忽略） |
| `build/signing/` | 证书与密码文件 | 否（已忽略，需单独备份） |
| `build/logs/` | 打包日志 | 否（已忽略） |
| `unpackage/` | 开发运行产物与缓存 | 否（仓库根 `.gitignore` 忽略） |
| `scripts/native-host/` | 精简宿主模板（文本配置、Gradle wrapper 与图标） | **是** |
| `scripts/*.sh` | 初始化与一键打包脚本 | **是** |
| `static/` | 运行时图片与音频 | **是** |
| `package/logo/` | 应用图标 | **是** |
| `docs/`、`README.md`、`AGENTS.md` | 文档 | 是 |

宿主缓存（`~/Library/Application Support/GameApp/...`）在仓库外，不提交；换机器或清理缓存后重新执行 `setup-native-host.sh` 即可。

## 11. 常见问题

| 现象 | 处理 |
| --- | --- |
| `UnsupportedClassVersionError ... class file version 65.0` | Gradle 正在用 JDK 17 执行；安装 JDK 21/25，设置 `JAVA_HOME`，或确认宿主 `gradle/gradle-daemon-jvm.properties` 存在并允许 Gradle 下载 JDK 25 |
| `No Java Runtime`（apksigner/keytool） | 脚本会设置 `JAVA_HOME`；手动执行时先 `export PATH="$JAVA_HOME/bin:$PATH"` |
| 找不到 HBuilderX CLI | 确认 `/Applications/HBuilderX.app/Contents/MacOS/cli` 存在，或用 `HBX_CLI` 指定 |
| CLI 提示「未检测到已打开的HBuilderX」 | 脚本会自动执行 `cli open --project` 并重试；仍失败时手动打开 HBuilderX，确认项目已加载后重跑 |
| CLI 返回 0 但没有更新资源 | 只认「编译成功 / 导出 android 成功」输出；脚本已做该检查，手动执行时不要只看退出码 |
| 找不到 Android SDK / build-tools | 设置 `ANDROID_HOME`，安装 Platform 36 与 Build-Tools 36 |
| 找不到宿主缓存 | 运行 `scripts/setup-native-host.sh --sdk <官方SDK.zip>` |
| SDK 缺少宿主需要的 AAR | 确认使用 5.26 官方 SDK；`setup-native-host.sh` 会列出缺失文件 |
| 发行资源版本与 manifest 不一致 | `manifest.json` 改完后重新运行脚本，或加 `--clean`；不要复用旧 `unpackage` |
| 启动后报 `GOAL is not defined` / 显示旧关卡 | 宿主 assets 残留旧编译产物；用脚本的 `rsync --delete` 重新同步，或删除宿主 `uniappx/src/main/assets/apps/<appid>/www` 后重打 |
| 点击「开始游戏」无反应、无声音 | 检查宿主是否有 `com.google.android.exoplayer:exoplayer-core:2.18.0`，以及 `uni-createInnerAudioContext` AAR；logcat 搜索 `NoClassDefFoundError` |
| APK 体积骤增 | 检查是否把 `build/`、`unpackage/` 或大尺寸 PNG/音频混入 `static/`；确认没有恢复完整示例宿主的全量依赖 |
| 安装时报签名冲突 | 新旧 APK 使用了不同证书；必须找回原 `build/signing` 证书，或先卸载旧版（会丢失本地存档） |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 同上；也可检查 `applicationId` 是否被改变 |
| API 37 模拟器弹出 16 KB 页面大小兼容提示 | 官方预编译 `.so` 未全部按 16 KB 对齐，系统以兼容模式运行；当前不影响功能，无法通过业务代码修复 |
| 云打包失败提示证书 | 证书别名/密码错误，或证书过期；证书不入库，由发版人本地保管 |

## 12. 云打包（备选）

本地打包不可用时，可在 HBuilderX「发行 → 原生 App-云打包」：

1. 选择 Android，勾选与 `manifest.json` 一致的 ABI。
2. 使用正式证书（`.keystore`）与别名；证书与密码不提交仓库。
3. 打包完成后把产物归档到 `build/`，命名 `huanle-games-<versionName>.apk`。

云打包按 manifest 模块声明裁剪，体积通常比完整宿小，但无法像本地脚本一样精确控制宿主模块与签名流程。日常发版优先使用本地一键脚本。
