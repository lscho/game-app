# 02 · 架构与渲染管线

本文描述页面与引擎的边界、游戏状态机、帧循环、坐标与布局、按钮系统、音频与存档。修改流程、渲染或输入相关代码前必读。果园的独立实现与三款新游戏共用外壳的对比见 [06-多游戏架构与新增游戏指南.md](06-多游戏架构与新增游戏指南.md)。

## 1. 分层

```
pages/index/index.uvue          游戏大厅（UVue 原生组件）
   └─ games[] → uni.navigateTo(route)
        ├─ pages/game/game.uvue        → game/orchard.js
        ├─ pages/bubble/bubble.uvue    → game/bubble.js   ┐
        ├─ pages/memory/memory.uvue    → game/memory.js   ├ 共用 game/engine.js
        └─ pages/band/band.uvue        → game/band.js     ┘
                    ↓
pages/<id>/<id>.uvue            游戏页胶水层
   ├─ uni.createCanvasContextAsync  取得 Canvas 2D 上下文（每页独立 canvas id）
   ├─ uni.getWindowInfo             取 DPR、窗口尺寸、安全区
   ├─ touchstart / touchmove / touchend → game.touchXxx
   └─ onReady / onHide / onBackPress / onUnload → game 生命周期方法
                    ↓
game/orchard.js                 果园引擎（独立实现，无框架依赖）
game/engine.js                  BaseGame 通用外壳 + 工具 + NativeAudio
   └─ game/bubble.js | memory.js | band.js：继承 BaseGame，只写玩法与场景
```

- 大厅是首页，只负责品牌展示、游戏列表与 `uni.navigateTo`；游戏页负责 Canvas 与生命周期，不包含大厅逻辑。
- 页面层不包含任何玩法或绘制细节；引擎层不注册页面生命周期钩子，但可以直接调用 `uni` 的存储与音频 API。
- 引擎是普通 ES Module，通过 `import { BubbleGame } from '../../game/bubble.js'` 引入，无打包器特殊处理。`engine.js` 不依赖任何页面，可被多个游戏同时引用。
- 每个游戏页的 Canvas id 必须唯一（`game`、`game-bubble`、`game-memory`、`game-band`），否则 `createCanvasContextAsync` 会取到错误的画布。

## 2. 初始化顺序

1. `onReady` 触发 `setupCanvas()`。
2. `uni.createCanvasContextAsync({ id: 'game-bubble', component: instance.proxy, success })` 回调中取 `context.getContext('2d')`；id 与页面模板中的 `<canvas id>` 一致。
3. 计算尺寸：
   - `dpr = min(pixelRatio, 3)`；
   - 宽高优先用 `canvas.offsetWidth/offsetHeight`，取不到时退回 `windowWidth/windowHeight`；
   - `canvas.width/height = CSS 尺寸 × dpr`，然后 `ctx.scale(dpr, dpr)`，使后续绘制统一使用 CSS 像素。
4. 安全区：`safeTop = safeArea.top`，`safeBottom = windowHeight − safeArea.bottom`。
5. 构造引擎实例：果园用 `new OrchardGame(...)`，新游戏用 `new BubbleGame(...)` / `MemoryGame` / `BandGame`，参数一致：`{ canvasContext, ctx, width, height, dpr, safeTop, safeBottom }`。
6. 构造函数内：初始化状态 → `layout()` → `resetLevelData()` → 加载图片 → 启动 `requestAnimationFrame`。新游戏的 `BaseGame` 还会在构造时创建 `NativeAudio` 与读取存档。

> 大厅页也使用 `uni.getWindowInfo().safeArea` 设置顶部/底部留白；新增页面时沿用同一安全区计算方式。

> 页面没有监听尺寸变化或旋转事件。修改为支持横屏/分屏前，需要在页面层补充 resize 处理并重建 Canvas 与引擎。

## 3. 状态机

状态由两个字段组成，避免组合爆炸：

```
state:     loading → start ⇄ levelselect
                       start → playing ⇄ paused
                       playing → (gameMode: ready → roundclear) → celebrating
                       celebrating → playing | start | levelselect
gameMode:  idle | ready | roundclear | celebrated
```

| state | gameMode | 画面 | 可交互 |
| --- | --- | --- | --- |
| `loading` | `idle` | 场景 + 「果园正在醒来…」 | 无（图片未就绪） |
| `start` | `idle` | 开始界面、伙伴货架、地图入口 | 开始、地图、静音 |
| `levelselect` | `idle` | 关卡地图浮层 | 关卡格、关闭 |
| `playing` | `ready` | 游戏 HUD、小兔子、水果 | 拖动、暂停、静音 |
| `playing` | `roundclear` | 通关动画（果园为彩虹揭晓；新游戏为场景淡出/卡片弹起） | 无 |
| `paused` | `ready` | 暂停卡片 | 继续、回首页、静音 |
| `celebrating` | `celebrated` | 庆祝卡片 + 持续彩带 | 继续探险/地图/首页、重玩 |

新游戏的 `roundclear` 由 `finishRound(delay)` → `beginRoundClear()` 进入，默认停留 1.6 秒后 `openCelebration()`；子类可在 `updateClear(dt)` 中播放自己的收尾动画。

关键约束：

- `pause()` 只接受 `playing + ready`；`roundclear` 期间不可暂停。
- `handleHide()`（页面 `onHide`）在游戏进行中自动暂停，其他状态只停音乐与语音。
- `handleBack()`（页面 `onBackPress`）：地图 → 关闭地图；游戏中 → 暂停；暂停/庆祝 → 回游戏开始页；在开始页返回 `false`，由框架回退到大厅；返回 `true` 时拦截系统返回。
- 顶部左侧返回按钮 `back` 调用 `requestExit()`：冻结当前画面、暂停 BGM/语音并弹出「要回大厅吗？」；`exit-cancel` 关闭弹窗并恢复音乐，`exit-home` 通过 `reLaunch` 回到大厅。确认框打开时按物理返回键等同于取消。
- `exitPrompt` 为真时 `update()` 提前返回并清空按钮，只保留 `exit-cancel` / `exit-home` 两个命中区，防止误触底层 HUD。
- `destroy()`（页面 `onUnload`）：`cancelAnimationFrame` + 销毁全部音频上下文，随后页面把 `game` 置空。
- 新游戏的 `handleBack()` 在开始页同样返回 `false`，因此物理返回会先回到大厅，再按一次才退出应用。

## 4. 帧循环

```js
loop(timestamp) {
  dt = clamp((timestamp - lastTs) / 1000, 0.001, 0.05)   // 最长 50ms，防止切后台后跳帧
  try { update(dt); draw() } catch (e) { console.error('Game frame error', e) }
  rafId = canvasContext.requestAnimationFrame(loopBound)
}
```

`update(dt)`：

1. `state === 'paused'` 时跳过所有时间推进（暂停即冻结）。
2. 否则推进 `time`，更新粒子/飘字/水花/彩带、云与花瓣。
3. `playing + ready` → `updatePlaying()`：小兔子跟随、生成、下落、接住/漏接判定。
4. `playing + roundclear` → `updateRoundClear()`：彩虹展开、水果淡出，1.35 秒后 `openCelebration()`。
5. 处理排队的语音（`pendingVoice`）。
6. 每帧末尾清空 `buttons`，等 `draw()` 重新注册。

`draw()` 按状态分支：`drawScene()` 恒常执行（天空、彩虹、云、山、树、地面、装饰），随后按状态叠加小兔子、水果、特效、HUD、弹层。场景与 HUD 的静态形状走 Path2D 缓存，见 [4.3](#43-静态场景与-hud-的-path2d-缓存果园)。

### 4.1 小兔子与接住判定（果园）

- 小兔子平滑跟随：`bunnyX += (targetX - bunnyX) × (1 − e^(−11·dt))`，接近 0.3px 时吸附；倾斜角由水平速度推导，限制 ±6°。
- 接住区域：`|fruit.x − bunnyX| ≤ catchHalf + fruit.r × 0.18` 且 `fruit.y ≥ catchY − fruit.r × 0.15`。
- `catchY` 由篮筐（兔子身体下部）位置推导，见 `layout()`。
- 落到 `groundY` 的未接住水果走 `missFruit()`。

### 4.1.1 新游戏的更新与命中

三款新游戏不重写 `update()`，只在 `updatePlay(dt)` 中推进自己的对象；点击命中统一走 `onTapInPlay(x, y)`：

| 游戏 | 对象推进 | 命中判定 |
| --- | --- | --- |
| 泡泡海洋 | 泡泡以 `speed` 上浮并正弦摆动，出屏即移除 | 点击点与泡泡圆心距离 ≤ `r + 14` |
| 动物翻翻乐 | 卡片 `flip` 插值、错误配对到 `wrongBackAt` 自动翻回 | 点击落在卡片矩形内（宽 × 1.18 高） |
| 小小乐队 | 节拍器计时、独奏回放逐音推进 | 点击落在乐器按键矩形内 |

- 新游戏不使用 `setTimeout`；所有延迟（翻回、独奏、过关）都由 `this.time` 推导，暂停时自然冻结。
- 每帧开始时 `buttons` 被清空，绘制时重新注册；`onTapInPlay` 只处理非按钮点击，按钮优先级由 `touchStart` 保证。

### 4.2 生成（果园）

- `updatePlaying()` 中 `startGrace` 归零后开始生成；同屏上限 `maxFruits`。
- `shouldSpawnBee()` 按 `hazardChance` 判定，场上最多 2 只，开局 1.6 秒内不生成。
- `spawnFruit()` 会避免与上一次生成点水平距离 < 90px（最多重试 6 次），减少「同一列连续掉落」的挫败感。

### 4.3 静态场景与 HUD 的 Path2D 缓存（果园）

远山、树、地面、草花每帧要执行近千次 Canvas 调用，在 App 端（DPR 最高 3）会明显拖慢水果下落等动画。果园因此把「关卡内不变的形状」一次性写进 `Path2D`，每帧只做 `fill`/`stroke`：

| 缓存字段 | 内容 | 使用位置 |
| --- | --- | --- |
| `scenery` | 远山、每棵树（树干/树冠/高光/果子各一层）、地面、草茎、每朵花 | `drawSceneryCache()` |
| `skyGradient` / `groundGradient` | 天空与地面渐变对象 | `drawSky()`、场景缓存 |
| `sunGlow` / `sunFacePath` / `sunRayPath` | 太阳光晕渐变、表情弧、12 条光芒 | `drawSunMoon()` |
| `rainbowPaths` | 6 条彩虹弧 | `drawRainbow()` |
| `cloudPaths` | 单位尺寸云形，绘制时 `translate` + `scale` | `drawClouds()` |
| `uiPaths` | 圆钮底/投影、章节图标、彩虹图标、进度点 | `drawCircleButton()`、`drawChapterIcon()`、`drawRainbowIcon()`、HUD |

关键约定：

- `buildSceneryCache()` 由 `buildDecor()` 末尾调用，因此在构造、`beginLevel()`、`goHome()` 时自动失效重建；**修改主题、关卡或布局参数后必须走这条路径**，不要单独改字段。
- `scenery` 是按原始绘制顺序排列的层数组（`{ type, path, style, width?, alpha? }`）。相邻树的树冠互相覆盖，所以每棵树单独成层；花朵按「每朵一组」写入花瓣与花心，保持交错摆放时的层级。合并成一层会改变画面，勿优化。
- `createPath()` 封装 `canvasContext.createPath2D()`。平台不支持（旧版基座、Web 预览）时返回 `null`，`buildSceneryCache()` 提前退出，`drawScene()` 自动退回逐帧绘制 `drawHills()` / `drawTrees()` / `drawGround()` / `drawGroundDecor()`，画面一致、只是更慢。`drawSceneryCache()` 抛错时同样置空 `scenery` 并走回退。
- Path2D 陷阱：同一路径里连续调用 `arc()` / `ellipse()` 会用直线连接子路径，必须先 `moveTo` 到弧起点；统一用 `arcOn()` / `ellipseOn()`，不要直接写 `path.arc(...)`。
- 同一层只能有一种颜色：彩虹图标每条弧颜色不同，存成路径数组分别绘制；太阳圆盘（只填充）与光芒（只描边）也必须分开，合并会给圆盘描上粗边。
- 单位尺寸路径（云、章节图标）在绘制时缩放，`lineWidth` 需按缩放比例换算（如 `lineWidth = 1.8 / 15`），否则描边会随缩放变粗。
- 新增静态装饰时写进 `buildSceneryPaths()` 并保持原绘制顺序；新增圆形图标或常用形状时加到 `buildUiPaths()`。只有每帧变化的对象（水果、粒子、兔子、彩带）才继续逐帧绘制。

性能参考（Chrome 实测，仅作相对比较）：单帧 Canvas 调用约 1153 → 510，`drawScene()` 约 873 → 207，帧耗时约下降 45%。

## 5. 坐标、布局与安全区

- 引擎内部一律使用 CSS 像素：宽 `this.w`、高 `this.h`，果园另有 `groundY`、`catchY`。
- `layout()` 中的关键公式（果园）：

| 量 | 公式 | 说明 |
| --- | --- | --- |
| `groundY` | `h − clamp(h × 0.115, 84, 112)` | 地面线 |
| `bunnyW` | `clamp(w × 0.47, 148, 198)` | 兔子宽度随屏宽变化 |
| `bunnyH` | `bunnyW × 250 / 220` | 图片原始比例 |
| `catchHalf` | `bunnyW × 0.41` | 接住判定半宽 |
| `minX` / `maxX` | `max(38, w × 0.1)` / `w − minX` | 兔子可移动范围 |

- `BaseGame.layout()` 的通用公式（三款新游戏）：

| 量 | 公式 | 说明 |
| --- | --- | --- |
| `headerTop` | `safeTop + 10` | 顶部 UI 起点 |
| `hudBottom` | `headerTop + 122` | 章节芯片 40 + 间距 8 + 进度条 36 + 间距 6 + 目标条 32 |
| `contentTop` | `hudBottom + 8` | 玩法区域上界 |
| `contentBottom` | `h − safeBottom − 14` | 玩法区域下界 |

- 新游戏在 `contentTop`–`contentBottom` 之间自行排布，并预留 HUD 高度：翻翻乐卡片从 `hudBottom + 76` 开始，乐队按键从 `hudBottom + 116` 开始，泡泡则全屏活动。
- 顶部 UI 从 `safeTop + 10` 开始；底部伙伴货架与按钮使用 `h − safeBottom`。
- 装饰位置用 0–1 归一化比例存储（`clouds`、`stars`、`petals` 等），绘制时乘 `w`/`h`，因此天然适配不同屏幕。
- HUD 目标条最大宽度 300–344，卡片最大宽度 342–390，避免大屏被拉满。

## 6. 按钮系统

Canvas 没有原生控件，按钮采用「绘制即注册」：

1. 每帧 `update()` 清空 `this.buttons = []`。
2. 绘制函数在原地画形状，并 `this.buttons.push({ id, x, y, w, h })`。
3. `drawPauseScreen()`、`drawCelebration()` 等在末尾用 `filter` 限定本层可点击的 id，屏蔽被遮挡的底层按钮。
4. 输入：
   - `touchStart`：命中按钮记 `pressedId`；否则在游戏中开始拖动。
   - `touchMove`：拖动更新 `targetX`；按住按钮移动超过 18px 取消按压。
   - `touchEnd`：仅当抬起点仍在同一按钮内才 `activate(id)`，避免误触。
5. `activate(id)` 是所有按钮的唯一分发点，id 包括：`start`、`map`、`close-map`、`level-N`、`sound`、`pause`、`resume`、`home`、`next`、`replay`。三款新游戏共用同一组 id，玩法内的点击由 `onTapInPlay()` 处理，不注册为按钮。

新增按钮：绘制时注册 id → 在 `activate()` 添加分支 → 必要时在所在弹层末尾过滤 `buttons`。

## 7. 音频

`NativeAudio` 统一管理（果园与 `game/engine.js` 各有一份实现，行为一致）：

- 懒加载：首次 `ensure()` 时创建 1 个 BGM（循环、音量 0.3）、1 个语音通道、若干音效（音量 0.95，`celebrate` 1.0，自动播放关闭）。新游戏的音效数量按 `CONFIG.sfx` 决定，泡泡 10 个、翻翻乐 10 个、乐队 14 个。
- 播放安全：`play/pause/stop` 全部包裹 `try/catch`，并把 Promise rejection 吞掉，避免真机抛错中断游戏。
- 静音：`muted` 写入 `bunny-native-muted-v1`（四款游戏共用）；静音时暂停 BGM 与语音，取消静音时若 `musicDesired` 为真则恢复 BGM。
- 语音：单通道，`playVoice(key)` 会先停止上一条并替换 `src`；`queueVoice(key, delay)` 在 `update()` 中按时间触发。
- `destroy()` 停止并销毁所有上下文，并清空 `voiceTimer` / `pendingVoice`。
- 每款游戏有独立的 `audioPath`，因此从大厅进入不同游戏不会共用 BGM 上下文；离开页面时 `onUnload` 必须调用 `destroy()`。

## 8. 存档

| 键 | 值 | 读取函数 | 写入点 |
| --- | --- | --- | --- |
| `bunny-native-progress-v1` | 果园：`{ unlocked: number, completed: number[] }` | `OrchardGame.readProgress()` | `saveProgress()`（过关时） |
| `bunny-native-friends-v1` | 果园伙伴 id 数组 | `readFriends()` | `openCelebration()` |
| `bunny-native-muted-v1` | 布尔值 | `readBoolean()`（果园与 `engine.js` 各一份） | `setMuted()` |
| `kids-bubble-progress-v1` | 泡泡：`{ unlocked, completed, best }` | `engine.js` 的 `readProgress()` | `BaseGame.saveProgress()` |
| `kids-memory-progress-v1` | 翻翻乐：同上 | 同上 | 同上 |
| `kids-band-progress-v1` | 乐队：同上 | 同上 | 同上 |

- 所有读取都做了 `try/catch`、类型校验与范围夹取（`unlocked` 夹在 1–`MAX_LEVEL`，`completed` 过滤非法值并去重）。
- `best` 是 `{ 关卡号: 最高分 }`；读取时只保留正数，写入时取 `max(旧值, 本次)`。
- 读取失败一律回退到初始值，不阻断启动。
- **修改结构**：递增键名版本（如 `-v2`），或在新读取函数中兼容旧值；同时更新本文与 `AGENTS.md`。四款游戏的进度互不影响，静音状态共享。

## 9. 确定性装饰

`buildDecor()` / `buildScenery()` / `buildStage()` 使用 `mulberry32(level × 7919 + 41)` 生成云、草、花、星、萤火虫、蝴蝶、花瓣、光柱、舞台灯光的初始位置与相位。同一关每次进入画面一致，减少「随机画面跳变」对儿童注意力的干扰。新增装饰请沿用该 RNG，不要用 `Math.random()`。

- 泡泡：`buildDecor()` 生成 5 道光柱与 10 颗浮游微粒，`beginLevel()` 时重建。
- 翻翻乐：`buildScenery()` 生成 4 朵云与 12 朵小花，`beginLevel()` 时重建。
- 乐队：`buildStage()` 生成 3 束灯光与 18 颗星星，构造与每次 `beginLevel()` 都重建。

## 10. 调试接口

果园在构造函数中挂载 `window.__orchardGame`；三款新游戏由 `BaseGame` 挂载 `window.__kidsGame`，并用 `window.__kidsGameType` 标识当前游戏（`bubble` / `memory` / `band`）。两者都带 `typeof window !== 'undefined'` 判断，发布版本保留。

果园方法（`window.__orchardGame`）：

| 方法 | 作用 |
| --- | --- |
| `debugState()` | 返回状态、关卡、机制、进度、按钮 id、存档等快照 |
| `debugCatchOne(key?)` | 直接结算一个水果（默认按当前机制取正确水果） |
| `debugDropFruit(key?)` | 在兔子正上方放一个慢速水果，便于观察接住动画 |
| `debugHitBee()` | 模拟接到蜜蜂 |
| `debugFinishLevel()` | 循环调用 `debugCatchOne()` 直到过关（最多 100 次） |
| `debugCorrectKey()` | 返回当前机制下的「正确答案」水果 |
| `startLevelFromMap(n)` | 从地图进入第 n 关，**受解锁限制**；锁定关卡只弹提示 |
| `beginLevel(n, runStart)` | 直接跳关，不做解锁校验；仅供调试 |

新游戏方法（`window.__kidsGame`，公共部分）：

| 方法 | 作用 |
| --- | --- |
| `debugState()` | 状态、关卡、进度、按钮、存档快照；子类会附加自己的字段 |
| `beginLevel(n, runStart)` | 直接跳关，不做解锁校验 |
| `startLevelFromMap(n)` | 从地图进入，受解锁限制 |

各游戏的专属调试方法：

| 游戏 | 方法 |
| --- | --- |
| 泡泡海洋 | `debugPopOne()` 戳破一个非带刺泡泡；`debugPopAll()` 反复戳直到过关 |
| 动物翻翻乐 | `debugMatchAll()` 自动配对全部剩余卡片 |
| 小小乐队 | `debugTapNext()` 敲当前正确乐器；`debugFinishLevel()` 敲完整段乐谱 |

真机 App 端 `window` 通常不可用，需通过浏览器预览或日志调试。

## 11. 已知边界

- 仅实现并验证了 Android App；H5/小程序未适配（`index.html` 存在但 Canvas 初始化依赖 App 端 API）。
- 暂停时不推进时间，但已排队的语音计时同样停止，恢复后继续，符合预期。
- 屏幕旋转、分屏、窗口缩放未监听；`pages.json` 已锁竖屏，因此当前不作为缺陷处理。
- 场景装饰与玩法对象都使用 DOM-free 的 Canvas 2D API，未使用任何 Uni 组件，因此无法通过 uni-app 的组件树调试。
- Path2D 缓存依赖 `canvasContext.createPath2D()`（uni-app x 4.25+）。更旧的基座或 Web 预览会自动退回逐帧绘制，画面一致但帧率更低；排查卡顿时先确认运行环境是否支持。
- 三款新游戏的页面胶水与果园一致，未做 Web 端适配；`engine.js` 依赖 `uni.*` 存储与音频，浏览器预览时需要 shim（见各游戏的离线自测脚本，不随仓库提交）。
- 新游戏共用同一套静态资源目录，图片 key 由各自 `CONFIG.assets` 独立声明；`star` 在泡泡与翻翻乐中都指向 `static/img/sea/star.png`，与果园的星星果不是同一张图。
