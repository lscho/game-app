### 2.7 加载机制

果园由 `OrchardGame.loadImages()` 维护 13 个 key → 路径的映射；新游戏由 `BaseGame.loadImages()` 遍历 `CONFIG.assets` 自动加载。两者都逐个 `canvasContext.createImage()`：

- 每张图 `onload` / `onerror` 都计数，全部完成（`imagesLoaded === imagesTotal`）后 `imagesReady = true`，状态从 `loading` 进入 `start`。
- 失败的条目置为 `null`，绘制层必须提供回退（水果画圆、泡泡画色块、卡片画问号、伙伴跳过）。
- **新增图片必须同时**：放入对应目录、加入果园的 `loadImages()` 映射或新游戏的 `CONFIG.assets`、在绘制代码中使用。
- 新游戏的 `assets` 数量即加载总数；新增一张图不需要改任何加载流程，只需在配置里加一行并 `this.images[key]` 使用。

## 3. 音效 `static/audio/`

| 文件 | 键 | 音量 | 触发 |
| --- | --- | --- | --- |
| `bgm.mp3` | BGM | 0.3，循环 | 开始游戏时启动；首页/地图中保持 |
| `catch-1.mp3` … `catch-6.mp3` | `catch-N` | 0.95 | 接住水果，按当前连击档位选第 N 个（>6 用 6） |
| `star.mp3` | `star` | 0.95 | 接住星星果、收集完成一轮 |
| `miss.mp3` | `miss` | 0.95 | 接错、漏接、撞蜜蜂 |
| `ui.mp3` | `ui` | 0.95 | 按钮点击、目标轮换 |
| `pause.mp3` / `resume.mp3` | `pause` / `resume` | 0.95 | 暂停 / 恢复 |
| `level.mp3` | `level` | 0.95 | 进入新关卡 |
| `friend.mp3` | `friend` | 0.95 | 庆祝时伙伴出场 |
| `celebrate.mp3` | `celebrate` | 1.0 | 过关瞬间 |

- 音效全部预创建（自动播放关闭），播放前先 `stop()` 再 `play()`，允许同一音效快速重复触发。
- 音量在 `NativeAudio.ensure()` 中统一设置：BGM `0.3`、普通音效 `0.95`、过关音效 `1.0`、语音 `1.0`；不要通过改 MP3 电平来调音量。
- 时长参考：`catch` ≈ 0.8 秒，`celebrate` ≈ 2.4 秒，果园 BGM ≈ 22.8 秒；新游戏 BGM 分别为泡泡 20.6 秒、翻翻乐 25.9 秒、乐队 17.7 秒、积木 19.1 秒、坦克 18.4 秒、连线 23.5 秒，均循环。
- 统一 MP3，建议 44.1kHz、单声道、96–128kbps；单个音效控制 20K 以内。

### 3.1 新游戏音效 `static/audio/{bubble,memory,band,blocks,tank,lines}/`

每款游戏的音效文件放在自己的目录，由 `CONFIG.sfx` 的键 → 文件名映射声明；`ui`、`pause`、`resume`、`level`、`celebrate`、`friend`、`nope` 在各目录中都有独立副本（内容可相同），保证 `audioPath` 只指向一个目录。

| 泡泡海洋 | `pop`、`splash` | 戳破泡泡 / 泡泡碎裂粒子 |
| 泡泡海洋 | `star` | 每连戳 4 个、闪亮泡泡 |
| 泡泡海洋 | `friend`、`nope` | 找到海洋朋友 / 戳到带刺泡泡 |
| 动物翻翻乐 | `flip`、`pick` | 翻牌 / 翻第一张 |
| 动物翻翻乐 | `match`、`nope` | 配对成功 / 配对失败 |
| 动物翻翻乐 | `friend` | 庆祝时伙伴出场 |
| 小小乐队 | `drum`、`xylophone`、`bell`、`maracas`、`tambourine`、`trumpet` | 敲对应乐器（音高不同） |
| 小小乐队 | `star`、`nope` | 每 4 连奏 / 敲错乐器 |

| 连线小方块 | `star` | 每连 4 对、全连完 |

## 4. 语音

### 4.1 果园 `static/audio/voice/`

| 模式 | 文件 | 触发 |
| --- | --- | --- |
| 开始 | `start.mp3` | 从首页开始新游戏（第 1 关） |
| 重玩 | `replay.mp3` | 终章后「再玩一次」 |
| 终章 | `final.mp3` | 通关第 20 关的庆祝 |
| 第 1 关庆祝 | `celebrate-1-{6..12}.mp3` | 第 1 关过关，按本关接住数夹取到 6–12 |
| 第 2 关庆祝 | `celebrate-2-{6..12}.mp3` | 第 2 关过关，同上 |

规则：

- 命名 `celebrate-{关卡}-{接住数}.mp3`，接住数超出范围时 `clamp(caught, 6, 12)`，因此 **6–12 每个数字都必须存在**，否则会 404 静默失败。
- 第 3 关及以后只播放 `friend.mp3` 与音效，不再播语音，避免音频文件数量膨胀。
- 语音为单通道：新语音前自动停止上一条；切页面、暂停、暂停恢复都会清理 `pendingVoice`。
- 语音音量固定 1.0，不受音效音量影响，但受全局静音控制。

### 4.2 新游戏 `static/audio/<id>/voice/`

六款新游戏使用同一套五个文件的固定契约，由 `BaseGame.openCelebration()` 统一触发：

| 文件 | 触发 | 说明 |
| --- | --- | --- |
| `start.mp3` | 开始新游戏 / 继续时进入第 1 关 | 介绍玩法，例如「戳一戳泡泡，找找海洋朋友」 |
| `clear.mp3` | 普通关卡过关 | 短鼓励，1–2 秒 |
| `great.mp3` | 每 4 关（第 4、8、12 关）过关 | 比 `clear` 更热烈的鼓励 |
| `final.mp3` | 第 16 关终章 | 通关祝贺 |
| `replay.mp3` | 终章后「再玩一次」 | 邀请再来一次 |

- 五个文件缺一不可；缺少时对应场景静默无声，不会报错，但会被验收清单判为不合格。
- 语音格式与果园一致：24kHz、单声道、48kbps MP3，单条 ≤ 48K；实际体积 5–24K。
- 语音为普通话女声（`say -v Tingting` 生成后统一转码），语速偏慢、句子短，符合 4–9 岁理解水平。
- 新增游戏时不要把语音复用为「跨游戏共享目录」：每款游戏自己的 `audioPath` 必须能独立定位到 `voice/`。

- [ ] 图片是透明 PNG，尺寸与现有资源同档，单张控制在 60K 以内（封面 ≤ 120K）。
